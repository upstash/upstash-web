{/* benchmark:lead:start */}

**Docs7 won 24 of 30 Google PageSpeed comparisons.** It also led in 10 of 10 DebugBear pairs and loaded faster in 11 of 15 Pingdom pairs.

{/* benchmark:lead:end */}

I tested documentation with images, video, long guides, code examples, and custom components on both platforms. Every performance number below comes from Google PageSpeed Insights, DebugBear, or Pingdom. The full results and original reports are at the end.

![Pages won in each test](/blog/docs7-vs-mintlify/wins.svg)

## The size of the gap

{/* benchmark:typical-results:start */}

Across the tested pages, Google's median score was **64 vs. 56 on mobile** and **92 vs. 80 on desktop**, both in Docs7's favor. Pingdom's median load time was **792 ms vs. 1,130 ms**. These are medians across pages, not a claim that every page improved by the same amount.

{/* benchmark:typical-results:end */}

![Median scores and load times](/blog/docs7-vs-mintlify/typical-results.svg)

Google and DebugBear report a Performance score out of 100. Higher is better. Pingdom measures load time in milliseconds. Lower is better. A 20-point score lead does not mean a page loads 20% faster.

## Why these pages?

A docs homepage tells us little about a long setup guide or an API reference. I chose pages by what they contain, so the test covers the work a documentation site has to do.

{/* benchmark:page-selection:start */}

- **Images, 3 pages.** Screenshots and framed images add downloads and can move the layout as they load.
- **Video, 1 page.** An embedded player and a component catalog add more than text to the initial load.
- **Long guides and steps, 2 pages.** Long text, accordions, tabs, and setup steps test a larger document.
- **Code and API references, 4 pages.** Code highlighting, tabbed examples, API fields, and callouts add rendering work.
- **Custom components, 3 pages.** Cards and custom React components test JavaScript and component rendering.
- **Diagrams and equations, 2 pages.** Mermaid and LaTeX need specialist rendering libraries.

{/* benchmark:page-selection:end */}

These groups describe the main content on each page. A page can contain several types of component. We measured the initial load, including the video page, without starting playback or scrolling through every image.

## How we tested

{/* benchmark:test-date:start */}

We tested on **September 15, 2026**, using the direct Docs7 and Mintlify hosted URLs. We selected 16 page pairs from the Upstash and Context7 documentation, with 15 pairs included in this post. We excluded 1 page pair because the content did not match. The download retains its results and the reason for exclusion.

{/* benchmark:test-date:end */}

- Google ran each URL three times on mobile and desktop. We use the median score for each page and device. These are [Lighthouse lab results](https://developers.google.com/speed/docs/insights/v5/about). The reports had no CrUX field data from real visitors.
- DebugBear ran each URL once on mobile, from US East, at 12 Mbps and 70 ms round-trip latency with a medium device. Service errors stopped the tests after 10 completed pairs. Its Lighthouse settings differ from Google's, so we keep the results separate.
- Pingdom ran each pair from the same city. Cities vary between pairs and are listed in the download. We repeated one pair after its first tests used different cities. Only the matched repeat counts.

For the overview charts, we take the median across the included pages for each host. For the content charts, we do the same within each group. Google uses each page's three-run median as the input. A group's median can fall between two measured scores.

Scores varied between runs. A one-point lead is too small to base a decision on. The download includes every run and each page's score range. Chat and analytics stayed as deployed and did not behave identically across hosts. CDN cache state was not controlled. This is a comparison of deployed sites, including their integrations.

GTmetrix and WebPageTest had too few matched results before their limits to support a comparison. We kept those attempts in the download.
