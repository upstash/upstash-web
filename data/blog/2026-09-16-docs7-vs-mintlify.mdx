**Docs7 won 13 of 16 Google PageSpeed comparisons.** In DebugBear, it led on 5 of 5 pages on mobile and 2 of 4 on desktop. In Pingdom, it loaded faster on 6 of 8 pages.

{/* benchmark:lead:end */}

I tested documentation with images, video, long guides, code examples, and custom components on both platforms. The charts use Google PageSpeed Insights, DebugBear, and Pingdom. Full results, report links, and smaller GTmetrix and WebPageTest samples are at the end.

![Pages won in each test](/blog/docs7-vs-mintlify/wins.svg)

## The size of the gap

{/* benchmark:typical-results:start */}

Across the tested pages, Google's median score was **64 vs. 53.5 on mobile** and **87 vs. 82 on desktop**. Pingdom's median load time was **659 ms vs. 733 ms**. Docs7 is listed first. These are medians across pages; the size of the lead differs by page.

{/* benchmark:typical-results:end */}

![Median scores and load times](/blog/docs7-vs-mintlify/typical-results.svg)

Google and DebugBear report a Performance score out of 100. Higher is better. Pingdom measures load time in milliseconds. Lower is better. A 20-point score lead does not mean a page loads 20% faster.

## Why these pages?

I fixed the page list before running the tests. It includes a short baseline page and pages that add video, screenshots, long text, or components. This lets us compare more than a homepage without filling the test with similar pages.

{/* benchmark:page-selection:start */}

- **Images, 1 page.** A reference page with nine screenshots tests image downloads and layout stability.
- **Video, 1 page.** An embedded player and a component catalog add more than text to the initial load.
- **Long guides and steps, 1 page.** A setup guide combines tabs, steps, code, and five screenshots.
- **Code and API references, 2 pages.** A long reference with 36 code blocks and a short command page with expandable fields test different document sizes.
- **Custom components, 2 pages.** Cards and custom React components test JavaScript and component rendering.
- **Diagrams, 1 page.** A Mermaid example turns source code into a diagram.

{/* benchmark:page-selection:end */}

These groups describe the main content on each page. A page can contain several types of component. We measured the initial load, including the video page, without starting playback or scrolling through every image.

## How we tested

{/* benchmark:test-date:start */}

We tested on **September 16, 2026**, using the direct Docs7 and Mintlify hosted URLs. We selected 9 page pairs from the Upstash and Context7 documentation, with 8 pairs included in this post. We excluded the math page: Docs7 rendered the equations, while Mintlify displayed raw math text. The download retains its results and the reason for exclusion.

{/* benchmark:test-date:end */}

- Google ran each URL three times on mobile and desktop. We use the median score for each page and device. These are [Lighthouse lab results](https://developers.google.com/speed/docs/insights/v5/about). The reports had no CrUX field data from real visitors.
- DebugBear tested **mobile and desktop**, from US East. Mobile used 12 Mbps, 70 ms round-trip latency, and 2× CPU throttling. Desktop used 100 Mbps, 2 ms, and no CPU throttling. Its settings differ from Google's, so we keep the results separate. Service errors limited the completed pairs; each chart row shows its own count.
- Pingdom used San Francisco for every included run. One initial run used London; we excluded it and repeated it from San Francisco. We paused when the service asked us to wait.

For the overview charts, we take the median across the included pages for each host. For the content charts, we do the same within each group. Google uses each page's three-run median as the input. A group's median can fall between two measured scores.

Scores varied between runs. A one-point lead is too small to base a decision on. The download includes every run and each page's score range. Chat and analytics stayed as deployed and did not behave identically across hosts. CDN cache state was not controlled. This is a comparison of deployed sites, including their integrations.

GTmetrix and WebPageTest each reached a free test limit. Their one complete page pair appears below, outside the overview charts. Failed attempts remain in the download. We repeated failed tests, not low scores.
