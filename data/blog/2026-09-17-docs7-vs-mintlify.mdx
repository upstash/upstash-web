**Docs7 won 33 of 34 Google PageSpeed comparisons, with 1 tie.** In Pingdom, it loaded faster on 12 of 17 pages. DebugBear favored Docs7 on 4 of 5 pages on mobile and 5 of 5 on desktop.

I tested documentation with images, video, long guides, code examples, and custom components on both platforms. The charts show the results; full tables and report links are at the end.

![Page wins: Docs7 leads on 17 of 17 Google mobile pairs, 16 of 17 desktop pairs, and 12 of 17 Pingdom pairs.](/blog/docs7-vs-mintlify/wins.svg)

## The size of the gap

Across the tested pages, Google's average score was **80.1 vs. 58.9 on mobile** and **94.9 vs. 88.4 on desktop**. Pingdom's average load time was **556 ms vs. 659 ms**. Docs7 is listed first.

![Average scores and load times for each service's completed page pairs.](/blog/docs7-vs-mintlify/typical-results.svg)

Google and DebugBear scores are out of 100; higher is better. Pingdom measures load time in milliseconds; lower is better.

In a second test set, Docs7 won 7 of 9 Pingdom comparisons across San Francisco, Frankfurt, and Tokyo, and all 8 DebugBear comparisons. These results appear separately in the tables below.

## Why these pages?

I chose pages to cover different types of documentation, then checked their content on both live sites before testing.

- A reference page with nine screenshots tests image loading and layout stability.
- A video page combines an embedded player with a custom component catalog.
- Four guides cover steps, release notes, a long CLI reference, and a setup flow with tabs and images.
- Five code and API pages cover long references, expandable fields, scheduling, retries, and SDK setup.
- Cards and a custom React badge test custom components. Separate examples cover tabs, accordions, and a file tree.
- A Mermaid page tests diagram rendering.

## How we tested

We compared **17 page pairs on September 17, 2026**, using the direct Docs7 and Mintlify hosted URLs.

- Google PageSpeed Insights ran 10 tests per URL on mobile and desktop through its API, for 680 tests in total. All used Lighthouse 13.4.1. We kept every valid run. We use each page's median score for both hosts, following [Google's guidance on repeated tests and medians](https://github.com/GoogleChrome/lighthouse/blob/main/docs/variability.md#run-lighthouse-multiple-times).
- Pingdom first ran one test per URL from San Francisco, then tested three page pairs once more in San Francisco and once in Frankfurt and Tokyo.
- DebugBear first ran five page pairs per device from US East, then five mobile and three desktop pairs. Each set used one run per URL and device.

The overview charts use the first test set. The overview and content charts use averages, with equal weight for each page. Each service uses its own test settings, so we keep their results separate.

These [lab tests](https://developers.google.com/speed/docs/insights/v5/about) measure initial page loads. Scores can vary between runs.
