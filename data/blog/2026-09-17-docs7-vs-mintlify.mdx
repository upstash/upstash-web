Documentation should get you to an answer quickly. As we built Docs7, we wanted to check how its generated pages performed against Mintlify on real documentation, including pages with screenshots, video, and custom components. A fast text-only page would not tell us much about those cases.

I tested **17 matching pages from the Upstash and Context7 docs** using Google PageSpeed Insights, DebugBear, and Pingdom. These services ran the tests on their infrastructure. We kept the same page paths and test settings for each host, repeated the Google tests 10 times per URL and device, and used the median rather than the best run.

## The results

**Docs7 won 33 of 34 Google page-and-device comparisons, with one tie.** Its average per-page score was **80.1 vs. 58.9 on mobile** and **94.9 vs. 88.4 on desktop**. DebugBear also favored Docs7 on all 10 tested page pairs on each device.

![Average per-page scores and page wins. Docs7 is orange; Mintlify is green.](/blog/docs7-vs-mintlify/typical-results.svg)

Pingdom measured full page load time from San Francisco, Frankfurt, and Tokyo. Most pages still have only one run per URL, so those results are [in the appendix](https://github.com/upstash/upstash-web/blob/101b417e46df9239e99bd24b0da68ee107594188/benchmarks/docs7-vs-mintlify.md#pingdom-exploratory-load-time-checks). They are useful observations, but too thin to support a regional speed claim.

## What we tested

We used two documentation projects, each hosted on both platforms:

- **Upstash:** [Docs7](https://upstash-docs.docs7.io/docs/introduction) and [Mintlify](https://upstash.mintlify.dev/docs/introduction).
- **Context7:** [Docs7](https://upstash-context7.docs7.io/docs/overview) and [Mintlify](https://context7.mintlify.dev/docs/overview).

The 7 Upstash pages cover screenshots, a video and component catalog, REST and SDK references, scheduling, and retries. The 10 Context7 pages cover cards, a custom React component, a library setup guide, a CLI guide, diagrams, steps, tabs, accordions, a file tree, and release notes.

We chose this set to exercise different parts of a documentation site. Images test download cost and layout stability. Long references test large pages and code blocks. Tabs, diagrams, and custom components add rendering and JavaScript work. These are deployed-site comparisons, not an isolated test of either renderer.

The [full page list and results on GitHub](https://github.com/upstash/upstash-web/blob/101b417e46df9239e99bd24b0da68ee107594188/benchmarks/docs7-vs-mintlify.md) link to **both the Docs7 and Mintlify URL in every row**, so you can inspect each pair.

## Why Docs7 can load faster

Docs7 compiles documentation into static HTML at build time. Cloudflare's [static-asset network](https://developers.cloudflare.com/workers/static-assets/) serves those files, so a request for a documentation page does not need to render the page on an application server. The browser receives the page content directly, with JavaScript for interactive features.

We also prepare responsive image sizes during the build, set image dimensions to reserve space, and defer images below the opening content. These choices reduce the work needed to show the first screen. Static delivery is part of the design; the browser's image, layout, and JavaScript work still matters.

The video and component catalog page shows what that means in the measurements. In Google's mobile tests, the median largest-content paint was **4.20 seconds on Docs7 vs. 12.91 seconds on Mintlify**. On desktop, Docs7 showed the largest content sooner and spent less time blocking the browser:

![Video-page desktop medians. Docs7 shows the largest content at 791 ms vs. 1,102 ms, with 493 ms vs. 682 ms of blocking time.](/blog/docs7-vs-mintlify/google-workflow-comparison.svg)

Mintlify painted the first content slightly earlier in this desktop comparison. The overall score reflects several metrics. These results show where the gap appeared, but do not isolate how much came from each architecture choice or tell us how Mintlify works internally.

## Method and full data

Google ran all **680 tests on September 17, 2026**, using Lighthouse 13.4.1. DebugBear and Pingdom results include follow-up runs on September 18. For repeated tests, we use the median for both hosts, following [Google's guidance on repeated runs](https://github.com/GoogleChrome/lighthouse/blob/main/docs/variability.md#run-lighthouse-multiple-times). Each summary gives every page equal weight and keeps devices, services, and locations separate.

These are initial-load lab tests. We did not play the videos or measure interaction latency. Cache state was not controlled, and paired runs were not always simultaneous. Results can vary.

[Read the full results on GitHub](https://github.com/upstash/upstash-web/blob/101b417e46df9239e99bd24b0da68ee107594188/benchmarks/docs7-vs-mintlify.md) for the 17 page pairs, test settings, run counts, all DebugBear and Pingdom report links, and the [680 Google measurements as CSV](/blog/docs7-vs-mintlify/google-runs.csv).
