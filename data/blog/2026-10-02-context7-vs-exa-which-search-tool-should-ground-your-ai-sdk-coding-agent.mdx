AI SDK 7 renamed `stepCountIs` to `isStepCount`. Next.js 16 renamed `middleware.ts` to `proxy.ts`. Models trained before these releases still write the old names, so coding agents need a search tool to look up the current API.

But that only helps if the search tool returns up-to-date docs. We tested Context7 and Exa on 22 API renames from 2025 and 2026, and checked every result for both the old name and the new one. We also ran a Claude agent with each tool and scored the code it wrote.

## Which returns more up-to-date docs, Context7 or Exa?

Context7 returns more up-to-date docs. We asked both tools 22 questions about APIs that were renamed or removed in 2025 and 2026. Only 1% of Context7's results used nothing but the old API name, against 9.8% of Exa's search results.

Here is the stale-only share for each setup:

![](https://cdn.bydefault.so/image-bIWkTB3l4xrqUrnjtG7gi.png)

The gap grows when you look at everything a single search hands to the model:

- **Clean results.** In 26 of 44 searches, everything Context7 returned used only current API names. Exa search managed that in 9 of 44, and exa-code in 10 of 44.
- **Live crawl.** Forcing Exa to crawl every page fresh did not help. It returned the same 43 stale results as the default setting.
- **Size.** A median Context7 search was 821 tokens. A median Exa search with the AI SDK tool's defaults was 8,733 tokens, about 10.6 times more.

This matters because the model has to read all of it. Without a search tool, 8 of the agent's answers to the same 22 questions used only the old API. With either search tool, that dropped to zero. But with Context7, the agent read 7.6 times fewer input tokens to get there.

## How do you test if a search tool is up to date?

We asked each tool about APIs that changed recently, then checked every result for both the new name and the old one it replaced. We only counted a result as current when it had the new name and not the old one.

We first tried a looser test that passed a search whenever the new name showed up anywhere in the results. With that, every setup looked almost perfect (Context7 passed 42 of 44 searches, Exa search 41, and exa-code 44). But most Exa searches returned both names at once. In 32 of 44 default Exa searches, the model got pages with the current API next to pages with the old one, and had to guess which one to trust.

For this test we used 22 real renames from the latest major versions of seven libraries. Each question names the library and its major version, just like a developer using that version would ask:

| Library | Old name | New name |
| --- | --- | --- |
| [AI SDK 7](https://ai-sdk.dev/docs/migration-guides/migration-guide-7-0) | `stepCountIs`, `system`, `onStepFinish`, `needsApproval`, `experimental_telemetry`, `cachedInputTokens`, `createGoogleGenerativeAI` | `isStepCount`, `instructions`, `onStepEnd`, `toolApproval`, `registerTelemetry`, `inputTokenDetails`, `createGoogle` |
| [Next.js 16](https://nextjs.org/docs/app/guides/upgrading/version-16) | `middleware.ts`, one-argument `revalidateTag`, `dynamicIO` | `proxy.ts`, `revalidateTag(tag, profile)` or `updateTag`, `cacheComponents` |
| [Vitest 5](https://vitest.dev/guide/migration/) | `test.sequential`, `bench` imported from `vitest`, `vitest/reporters` | `concurrent: false`, `bench` from the test context, `vitest/node` |
| [ESLint 10](https://eslint.org/docs/latest/use/migrate-to-10.0.0) | `context.getFilename()`, `context.getSourceCode()`, `.eslintrc` | `context.filename`, `context.sourceCode`, `eslint.config.js` |
| [Vite 8](https://vite.dev/guide/migration) | `rollupOptions`, `transformWithEsbuild` | `rolldownOptions` or `codeSplitting`, `transformWithOxc` |
| [Prisma 7](https://www.prisma.io/docs/orm/more/upgrade-guides/upgrading-versions/upgrading-to-prisma-7) | `prisma-client-js`, `$use`, `url = env(...)` in the schema | `prisma-client`, `$extends`, `PrismaPg` adapter |
| [LangChain v1](https://docs.langchain.com/oss/python/migrate/langchain-v1) (Python) | `create_react_agent` | `create_agent` |

We ran each question twice through four search setups:

1. **Context7 Search** with only the question, no library or version hint, returning plain text.
2. **Exa search** through the `webSearch()` tool from `@exalabs/ai-sdk` with its defaults: 10 results, up to 3,000 characters of text each, and a live crawl only as a fallback.
3. **Exa search with live crawl on**, so Exa fetched every page fresh instead of using its cache.
4. **exa-code**, Exa's code search endpoint, asked for 5,000 tokens of context.

We sorted each result, and each full search payload, as current-only, mixed, stale-only, or neither:

![](https://cdn.bydefault.so/drawing-HMYJ9eaJWbHAwqtY4lgn0.png)

Then we gave the same 22 questions to a Claude Sonnet 5.5 agent built with AI SDK 7, once with no tool, once with Context7, and once with Exa, and scored the final answer the same way.

## What did the freshness benchmark show?

Context7 gave the model clean, current docs far more often than any Exa setup. Its payloads were current-only in 26 of 44 searches, and only 2 of its 201 snippets used nothing but an old name.

Here are the results for all four setups across both runs:

| Setup | Current-only payloads | Mixed payloads | Stale-only results | Results with any old name | Median tokens | Median latency |
| --- | --- | --- | --- | --- | --- | --- |
| Context7 | 26 / 44 | 16 / 44 | 2 / 201 (1.0%) | 22 / 201 (10.9%) | 821 | 4.5 s |
| Exa search | 9 / 44 | 32 / 44 | 43 / 440 (9.8%) | 120 / 440 (27.3%) | 8,733 | 1.9 s |
| Exa, live crawl on | 5 / 44 | 35 / 44 | 43 / 440 (9.8%) | 119 / 440 (27.0%) | 8,592 | 10.2 s |
| exa-code | 10 / 44 | 34 / 44 | 37 / 395 (9.4%) | 115 / 395 (29.1%) | 4,888 | 1.2 s |

Exa was faster though. A default Exa search took 1.9 seconds, compared to 4.5 seconds for Context7. exa-code also put a current-only result first more often (34 of 44 searches, compared to 28 for Context7). None of the setups ever put a stale-only result first.

But after the first result, Exa returned 43 stale-only results, from pages like these:

- **Old pull requests and commits.** A [2024 Vite pull request](https://github.com/vitejs/vite/pull/16274) tells you to set `rollupOptions` for manual chunks, and a 2023 Vitest commit adds `test.sequential`. Both showed up for Vite 8 and Vitest 5 questions.
- **New blog posts that teach the old API.** A Next.js caching post [published in May 2026](https://nextjslaunchpad.com/article/nextjs-cache-not-revalidating-server-action-fix) calls `revalidateTag('order')` with one argument, which Next.js 16 deprecated. An AI SDK 7 tool approval post from July 2026 uses `needsApproval`.
- **Unofficial mirrors of official docs.** A copy of the AI SDK docs on a third-party host still shows `stepCountIs` and `experimental_telemetry`.
- **Other libraries.** The OpenAI Agents SDK also has a `needsApproval` option, and its docs showed up for an AI SDK question.

Only 209 of Exa's 440 results came from the library's own docs site or GitHub repo. The rest came from the open web:

![](https://cdn.bydefault.so/image-kPY4WhWHW4eqdtQuk60h5.png)

Context7's two stale-only snippets were the same page fetched twice: an AI SDK cookbook recipe on the main branch of the vercel/ai repo that still uses `needsApproval`. Exa returned that recipe too.

## Does fresher search change the code an agent writes?

Yes. Without a search tool, 8 of the agent's 22 answers used only the old API. With Context7 or Exa, none did. With Context7, the agent read 82,011 input tokens across all 22 questions to get there, compared to 621,299 with Exa.

For example, for the first question, "How do I stop a generateText tool loop after 3 steps in Vercel AI SDK 7?", each agent wrote this line:

```text
No tool:   stopWhen: stepCountIs(3), // stop after 3 steps
Context7:  stopWhen: isStepCount(3), // stop the loop after 3 steps
Exa:       stopWhen: isStepCount(3), // stop the tool loop after 3 steps
```

Without search, the model still writes the AI SDK 6 name, because that's what it learned in training. With either search tool, no answer used only the old API:

| Agent | Current-only answers | Stale-only answers | Mixed answers | Input tokens, 22 questions | Tool calls |
| --- | --- | --- | --- | --- | --- |
| No tool | 1 / 22 | 8 / 22 | 13 / 22 | 919 | 0 |
| Context7 | 7 / 22 | 0 / 22 | 15 / 22 | 82,011 | 38 |
| Exa | 5 / 22 | 0 / 22 | 17 / 22 | 621,299 | 42 |

Most mixed answers had current code plus a short note naming the old API it replaces. Under our strict rule, that note alone makes the answer mixed. If we only score the code blocks, the Exa agent wrote current-only code for 20 questions and the Context7 agent for 18.

Context7's one stale code answer was for the approval question. The agent searched for human-in-the-loop examples, got the same AI SDK cookbook recipe that still uses `needsApproval`, and copied it. That page is outdated in the AI SDK's own repo.

So both tools fix the stale answers the model gives on its own. Context7 gets the agent there with a lot less text to read, and a smaller share of that text is stale.

## Why doesn't Exa's live crawl fix stale results?

A live crawl gets Exa a fresh copy of the page, but the page still teaches the same API. A blog post written for Next.js 15 still calls `revalidateTag` with one argument, even if Exa fetched it a second ago.

Even after a live crawl, a stale page reaches the agent like this:

![](https://cdn.bydefault.so/drawing-vuP9tlKozi_4ZJIdLyNzn.png)

Exa controls freshness with one setting, `maxAgeHours`. Setting it to 0 [makes Exa crawl every page live](https://exa.ai/docs/contents/quickstart), -1 uses only the cache, and leaving it out crawls live only when Exa has no cached copy. We ran the live-crawl setup with it set to 0:

- The stale-only results stayed at 43 of 440, the same as the default.
- Current-only payloads dropped from 9 of 44 to 5 of 44.
- The median search time went from 1.9 seconds to 10.2 seconds.

The stale pages come from where Exa looks. Exa search ranks pages from across the open web, and exa-code uses [a code index built from GitHub and Exa's web index](https://exa.ai/blog/exa-code). Some of those pages are 2024 pull requests or unofficial doc mirrors. Others are blog posts from this year that still use last year's API. Even [Exa's own AI SDK quickstart](https://exa.ai/docs/integrations/vercel/ai-sdk) still uses `stepCountIs`, the AI SDK 6 name.

Exa's freshness tools are good for content that changes on the page itself, like news, prices, or a changelog. But for a coding agent, when a page was crawled and which API version it uses are two different things.

## How does Context7 keep docs current?

Context7 only indexes docs that the library's own team publishes, and the library owner decides which version is the latest. It refreshes the most popular libraries once a day, and only keeps older versions in the index when the owner asks for them.

- **Refresh on request.** When anyone requests a library, Context7 checks when its docs were last updated. If they are older than a threshold, [a background refresh starts](https://context7.com/docs/library-updates). The threshold is 1 day for the top 100 libraries, 15 days for the top 1,000, 30 days for the top 5,000, and 45 days for the rest.
- **Owner control.** Library owners can [add a GitHub Action that refreshes the docs on every push](https://context7.com/docs/adding-libraries), so a new release is indexed when it ships. Owners also [decide which version is the latest](https://upstash.com/blog/context7-search) and how their docs are parsed.
- **One version per library by default.** A version analyzer finds docs that cover several versions and [keeps only the newest one](https://upstash.com/blog/context7-quality-and-safety). Older versions stay available only when the owner sets them up.
- **First-party sources.** Context7 indexes official docs sites, product websites, and API references. Forum threads and other third-party pages stay out, and every snippet is scanned for prompt injection before it goes in.

A new release reaches the agent through this path:

![](https://cdn.bydefault.so/drawing-Y4p34GVSbI3iZpMXOjvjA.png)

The refresh runs in the background, so the request that triggers it still gets the existing docs while the update runs. Here are the thresholds from the docs:

![](https://cdn.bydefault.so/image-k3ulhLS4pbDhblhxDJZd2.png)

The first-party rule explains most of the benchmark gap. The third-party pages behind Exa's stale results never enter Context7's index.

Version hints close the other gap. The Search API accepts a `library` and a `version`, and with one library the version is strict. With no hint, the Next.js 16 redirect question returned snippets with neither name. With a hint, it returns the `proxy` docs:

```ts
import { Context7 } from '@upstash/context7-sdk'

const context7 = new Context7({ apiKey: process.env.CONTEXT7_API_KEY })

const result = await context7.search(
  'How do I redirect requests before they reach a route?',
  { libraries: ['next.js'], version: '16', type: 'txt' }
)

console.log(result.split('\n').slice(0, 20).join('\n'))
```

The first lines it printed:

```text
Library: /vercel/next.js/v16.2.9

### Redirecting Requests with Next.js Proxy

Source: https://github.com/vercel/next.js/blob/v16.2.9/docs/01-app/03-api-reference/03-file-conventions/proxy.mdx

This snippet demonstrates how to use the `proxy` function to redirect incoming requests to a different URL. The `config` object specifies a matcher to apply this proxy to specific paths, such as all requests under `/about/`.

import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

// This function can be marked `async` if using `await` inside
export function proxy(request: NextRequest) {
  return NextResponse.redirect(new URL('/home', request.url))
}
```

Version `16` resolved to Next.js 16.2.9, and the source link points to that exact tag.

## How do I add Context7 to an AI SDK coding agent?

The agent needs one tool that calls Context7 Search with the question and an optional library and version. The model fills in the hints when it knows them, and Context7 returns a short text payload it can read directly.

Here's a complete agent with AI SDK 7 and the [Context7 TypeScript SDK](https://context7.com/docs/sdks/ts/getting-started):

```ts
import { anthropic } from '@ai-sdk/anthropic'
import { generateText, isStepCount, tool } from 'ai'
import { Context7, Context7Error } from '@upstash/context7-sdk'
import { z } from 'zod'

const context7 = new Context7({ apiKey: process.env.CONTEXT7_API_KEY })
const searchInput = z.object({
  query: z.string(),
  library: z.string().optional(),
  version: z.string().describe('Requires a library hint').optional()
})

type SearchInput = z.infer<typeof searchInput>

async function searchDocs({ query, library, version }: SearchInput): Promise<string> {
  try {
    return await context7.search(query, {
      libraries: library ? [library] : undefined,
      version: library ? version : undefined,
      type: 'txt'
    })
  } catch (error) {
    if (error instanceof Context7Error && error.status === 404) return 'No documentation found. Try another query or version hint.'
    throw error
  }
}

const result = await generateText({
  model: anthropic('claude-sonnet-5-5'),
  instructions: 'Use searchDocs before answering. Answer with a short code example using the current API.',
  prompt: 'How do I make one test run sequentially when concurrency is enabled in Vitest 5?',
  tools: {
    searchDocs: tool({
      description: 'Search library documentation. Library and version hints are optional.',
      inputSchema: searchInput,
      execute: searchDocs
    })
  },
  stopWhen: isStepCount(5),
  maxOutputTokens: 1000
})

for (const step of result.steps) {
  console.log(`Step ${step.stepNumber}:`)
  let toolCalls = 0
  for (const content of step.content) {
    if (content.type !== 'tool-call') continue
    toolCalls++
    console.log(`${content.toolName} ${JSON.stringify(content.input)}`)
  }
  if (!toolCalls) console.log('(no tool calls)')
}

console.log('Answer:')
console.log(result.text.split('\n').slice(0, 15).join('\n'))
```

The tool sends the version only when a library is set, because the Search API needs a library for a version hint. A 404 means Context7 found no docs, so the tool tells the model to try again instead of throwing.

The agent made one search and answered:

```text
Step 0:
searchDocs {"query":"run test sequentially when concurrent enabled (test.sequential)","library":"vitest","version":"5"}
Step 1:
(no tool calls)
Answer:
In Vitest 5, pass `{ concurrent: false }` as a test option. This opts the test out of concurrency, whether it comes from the config or from a parent suite.

import { describe, test } from 'vitest'

// Works even if `sequence.concurrent: true` is set in the config
test('runs on its own', { concurrent: false }, async () => {
  // ...
})
```

Even though the model put the old name, `test.sequential`, into its own search query, Context7 still returned the Vitest 5 docs, and the answer uses `concurrent: false`.
