<Summary>
A side-by-side comparison of 15 AI agent sandboxes, last checked in November 2026 against each provider's docs and pricing pages (sources at the end).

- **Upstash Box is the best overall option on feature set and price.** It has the broadest agent tooling of the fifteen (a built-in coding agent, git-to-PR, a managed browser, cron, secret injection, MCP) on a persistent computer that is quick to set up and easy to plug into your own agent. A few hard filters point elsewhere: a separate kernel per tenant, a GPU, your own cloud, or memory that survives a pause. The table below maps each need to the providers that meet it.
- **Billing is the biggest hidden difference.** Most providers bill wall-clock CPU and memory, while Cloudflare, Fly Sprites, Tensorlake, Upstash Box, and Vercel meter CPU by actual use. Box also leaves memory free and offers a flat $0.0111 an hour for an always-on box, which puts it among the lowest-cost rows in the worked example below.
- **Isolation is three designs, not a ranking.** Hardware VMs with their own kernel (Blaxel, Cloudflare, E2B, Fly Sprites, Freestyle, Koyeb, Namespace, Tensorlake, Vercel, Kata on Northflank for CPU sandboxes), gVisor's userspace kernel (Beam, Modal), and hardened containers (Daytona by default, Upstash Box).
</Summary>

**Runloop is winding down.** Its docs say transition support for existing customers runs through November 13, 2026, with [migration guides](https://docs.runloop.ai/docs/transitions/overview) to Tensorlake, Modal, and Freestyle, and its benchmark product is discontinued. Upstash Box could also be a good fit for teams moving off it, since it covers the same agent-running, secret-injection, and MCP columns in the tables below. The Runloop rows are kept for reference and for anyone migrating off it, but it is left out of the recommendations.

What each column is telling you:

**Isolation** is three designs, not a ranking: a VM with its own kernel, gVisor's userspace kernel, or a hardened container. Most providers run a VM. Daytona (by default) and Box run hardened containers, each with its own filesystem, process tree, and network namespace.

**Cold start** is what vendors lead with and what matters least, since booting is a fraction of the time a task spends cloning, installing, and calling a model. The figures are not like for like: they mix create-to-first-command, resume-from-standby, and time-until-an-agent-connects, and each is the vendor's own claim except the Box row, which we measured with five runs from Europe in September 2026.

**Billing basis** is the one that surprises people at scale. Wall-clock charges for every second the sandbox is up, including the minutes it waits on a model; active CPU charges only for what the code burns. Among the active-CPU providers, memory is still billed while the sandbox is up on all but Box.

**Idle cost** is what you pay between sessions, usually storage for the saved disk. Providers with no pause state keep charging the full rate until the sandbox is deleted.

**Session cap** is easy to miss until it bites: an hour is fine for a code interpreter, wrong for a long task, and the longer cap is often a paid plan away. Seven of the fifteen, Box included, have no cap at all.

**What survives a pause** decides how you structure a session: filesystem only means restarting processes, memory as well means a loaded model is still there, nothing means starting from a snapshot each time. Blaxel, Box, E2B, Tensorlake, and Vercel are the ones built around pausing and coming back.

**Agent built in** separates platforms that run an agent behind an API you call with a prompt from those that only let you install one. "CLIs preinstalled" is the middle ground. Box is on the yes side, and Runloop's Broker was before the wind-down.

**Snapshot / fork** makes parallel work cheap: set up once, snapshot, then start ten sandboxes from that state. Whether it carries memory as well as disk decides whether those ten start warm or cold.

**Custom images** move setup to build time. Most providers take any Docker image or Dockerfile. Box, Fly Sprites, and Freestyle work differently: Box offers per-runtime images plus snapshots, with custom images planned.

**Egress control** is the column to read closely if the sandbox runs code you did not write. Almost every provider starts open; Freestyle and Cloudflare (SDK 1.0) start closed, and Beam, Box, Cloudflare, Daytona (Tiers 3–4), E2B, Modal (alpha), and Vercel let you change the policy on a running sandbox.

**Built-in tooling** is the gap between a machine and a runtime. It ranges from a code interpreter and preview URLs to browsers, desktops, credential gateways, and agent runners. The next section breaks the agent-specific part down.

GPUs inside the sandbox: Beam, Daytona, Koyeb, Modal, and Northflank, plus Tensorlake by request. Blaxel, Box, E2B, Namespace, and Sprites are CPU-only.

**Run a coding agent with one call** has three levels: you bring the agent, the CLIs are preinstalled and you parse stdout, or the platform runs the process for you. Box exposes it as an SDK method with a typed result; Runloop's Broker runs the process and you wire the event streams.

**Typed output** lets one agent's answer feed the next step without a parser in between. Box takes a Zod or Pydantic schema in the SDK and returns a validated object; elsewhere it comes from the agent or framework you run inside.

**Scheduled runs in the sandbox** suit agents that work on a cadence rather than on a request. Blaxel and Box have cron inside the sandbox, and Box can also schedule an agent run; Beam, Northflank, and Tensorlake schedule at the platform level.

**Secrets kept off the sandbox** matters because the obvious approach is the unsafe one: an environment variable is readable by the code the model just wrote. A host-side proxy that injects the credential keeps it out of reach, and most providers here now have some form of it.

**Managed browser** decides whether web work is a feature or a Chromium install you maintain. Box ships one, as did Runloop; E2B documents Kernel's cloud browsers, Daytona and Tensorlake give you a VNC desktop instead, and Blaxel has browser templates.

**Git-to-PR helper** is the difference between a finished task and a diff sitting in a container. Daytona wraps git operations and Vercel ships `git` and `gh` in the image; Box is the one with a `createPR` call.

**MCP** is two questions in one heading: driving the sandbox from an MCP client, and giving the agent inside MCP tools. Box does both; Blaxel, Daytona, Fly Sprites, and Namespace offer a control server, and E2B a tools gateway.

As an example of what the built-in route looks like, here is a full task on Box: clone, branch, run the agent, commit, push, open the pull request, with the run's cost attached:

```ts
import { Agent, Box } from "@upstash/box"

const box = await Box.create({
  runtime: "node",
  agent: { harness: Agent.ClaudeCode, model: "anthropic/claude-fable-5" },
  git: { token: process.env.GITHUB_TOKEN },
  attachHeaders: { "api.stripe.com": { Authorization: `Bearer ${process.env.STRIPE_KEY}` } },
})

await box.git.clone({ repo: "https://github.com/your-org/your-repo", branch: "main" })
await box.cd("your-repo")
await box.git.exec({ args: ["checkout", "-b", "fix/null-token"] })

const run = await box.agent.run({ prompt: "Fix the null-token bug in src/auth.ts and add tests" })

await box.git.commit({ message: "fix: handle null token in auth" })
await box.git.push({ branch: "fix/null-token" })
const pr = await box.git.createPR({ title: "Fix null token bug", base: "main" })

console.log(pr.url, run.cost.totalUsd)
```

On providers without the git and agent helpers, the same flow is your own code around `exec`: shell out to git, stream the agent's output, parse it, then call the GitHub API yourself. That is more code, and also more control over the loop.

The rate card is the wrong thing to compare. Agent work comes in bursts: the CPU is busy for a few seconds per tool call and idle while the model thinks. What matters is what you pay for the idle time.

Next are Beam on its Shared tier (~$0.044), Cloudflare (~$0.052), Tensorlake Pro (~$0.053), and Koyeb (~$0.058), and the highest are Modal and Runloop. Modal bills max(request, actual) per second, so with no resource request the mostly idle hour drops to roughly $0.03 to $0.12 depending on memory in use (our estimate from its 0.125-core default request). Model usage is separate everywhere: none of the fifteen includes model tokens in the sandbox price, and on Box agents run on your own provider key.

## How to choose

For most agent workloads, start with Upstash Box: it is the best overall option on feature set and price. If you have a constraint you cannot move, start from that instead:

1. **A separate kernel per untrusted tenant.** Blaxel, Cloudflare, E2B, Fly Sprites, Freestyle, Koyeb, Namespace, Tensorlake, or Vercel. Beam (by default) and Modal use gVisor, a userspace kernel on a shared host kernel.
2. **A GPU in the sandbox.** Beam, Daytona, Koyeb, Modal, or Northflank.
3. **Your own cloud.** Beam, Blaxel (bring-your-own-metal), Daytona, E2B (Enterprise), Northflank, or Tensorlake.
4. **State that must survive in RAM.** Blaxel, E2B, Freestyle, or Tensorlake.
5. **The sandbox has to live inside your platform.** Cloudflare, Modal, or Vercel Sandbox.
6. **A persistent computer for your agent that is quick to set up and easy to plug in.** Upstash Box: TypeScript and Python SDKs, a CLI, an MCP server, and SSH, with your own agent loop or a built-in coding agent, plus git-to-PR, a browser, and cron when you want them.
7. **An agent that mostly waits on a model.** An active-CPU provider: Upstash Box (memory free as well), Cloudflare, Fly Sprites, Tensorlake, or Vercel.
8. **An always-on sandbox for your own agent.** An Upstash Box keep-alive box at a flat $0.0111/hour (2 vCPU / 4 GB), or Beam (Shared tier), Koyeb, or Northflank on per-hour rates.

import { Agent, Box } from "@upstash/box"

const box = await Box.create({

const run = await box.agent.run({

## FAQ

### What is the cheapest sandbox for AI agents?

In the 2 vCPU / 4 GB configurations we priced, Upstash Box. For an hour that mostly waits on a model (about 10 core-minutes of real work) it is about $0.017, because it bills active CPU only and leaves memory free; the next lowest are Beam's Shared tier at about $0.044 and Cloudflare at about $0.052. Fly Sprites bills memory actually in use, so a light process there can cost less. For a sandbox that stays on all the time, a keep-alive box is a flat $0.0111 per wall-clock hour, against about $0.044 on Beam Shared and $0.058 on Koyeb.

### How do AI sandbox providers bill?

Two models. Wall-clock billing (Daytona, E2B, Modal, Northflank and most others) charges vCPU and memory for every second the sandbox is up. Active-CPU billing (Cloudflare, Fly Sprites, Tensorlake, Upstash Box, Vercel) charges CPU only while code runs; of these, Box does not charge for memory and the others do.

### Which AI sandbox has the strongest isolation?

The ones that give each sandbox its own kernel in a hardware VM: Blaxel, Cloudflare, E2B, Fly Sprites, Freestyle, Koyeb, Namespace, Tensorlake, Vercel Sandbox, and Northflank's CPU sandboxes (Kata). Beam (by default) and Modal use gVisor. Daytona (by default) and Upstash Box use hardened containers.

### Which sandboxes have a coding agent built in?

Upstash Box runs Claude Code, Codex, OpenCode, Cursor or a custom harness with one call and returns a typed result. Runloop's Broker starts and manages an agent process, but Runloop is winding down. Vercel Sandbox, Fly Sprites and Koyeb preinstall agent CLIs without a run API.

### Which AI sandboxes support GPUs?

Beam, Daytona, Koyeb, Modal and Northflank, plus Tensorlake by request. Blaxel, E2B, Fly Sprites, Namespace and Upstash Box are CPU-only.
