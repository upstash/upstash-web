<Summary>
If your AI agent writes and runs code, it needs a real computer to run it on, one that can't touch your own systems when the model does something wrong. That's a sandbox.

A year ago there were only a few. Now there are dozens, and they don't line up neatly. Each one is built around a different strength: cold-start speed, GPU access, strong isolation, edge latency, instant forking, or just getting an agent running fast.

These are the top ten sandbox providers of 2026, with what each is good at and when to pick it. For most agent workloads, Upstash Box is the best overall option on feature set and price: a persistent computer that is quick to set up, works with your own agent or runs one for you, and comes with git, a browser, schedules, and secret injection built in. The others are strong picks for specific needs such as GPUs, your own cloud, or a particular ecosystem.

One of the ten, Runloop, is winding down as of November 2026 and is kept only with a notice.
</Summary>

"Sandbox for AI agents" went from a niche phrase to a crowded category in about a year. The reason is simple: the moment an agent can run shell commands, you have to decide *where* those commands run. And "on my server" stops being a safe answer the first time a model deletes the wrong files or leaks a key.

What's interesting is how differently the providers answered that. Some treat the sandbox as a security boundary and put everything into isolation. Some treat it as raw compute and chase the lowest cold start or the cheapest GPU. Some put the whole agent inside the box and just hand you a prompt.

They're sold under one label, but they're built for different jobs. So "which one is best" is the wrong question. The right one is "best at *what*."

Here are the top ten, each with what it's built for and when to pick it.

## Upstash Box: a persistent cloud computer for coding agents

[Upstash Box](https://upstash.com/docs/box/overall/quickstart) is a cloud computer you hand to an agent: a persistent Linux box with a shell, a filesystem, git, a browser, SSH, and public URLs. It pauses when idle and wakes weeks later with its files intact, so an agent can pick up where it left off.

It's **quick to get started**. One call creates a box, and the next one runs a command in it, from a TypeScript or Python SDK, a CLI, or an MCP server:

```ts
import { Box } from "@upstash/box"

const box = await Box.create({ runtime: "node" })
const run = await box.exec.command("node -e 'console.log(2 + 2)'")
console.log(run.result) // "4"
```

It's also **easy to plug in**. Drive the shell, code, and file APIs from your own agent loop, use it as the sandbox for the Vercel AI SDK, LangChain Deep Agents, Claude Managed Agents, or the OpenAI Agents API, or connect the coding agent you already use over MCP or SSH. The box doesn't care which model or framework is on the other end.

If you'd rather not build the agent loop at all, the box can run the agent for you. Pick a harness (Claude Code, Codex, OpenCode, or your own, such as Aider, Gemini CLI, or Goose) and a model, then send a prompt:

```ts
import { Agent, Box } from "@upstash/box"

const box = await Box.create({
  runtime: "node",
  agent: { harness: Agent.ClaudeCode, model: "anthropic/claude-opus-4-8" },
  git: { token: process.env.GITHUB_TOKEN },
})

await box.git.clone({ repo: "github.com/your-org/your-repo" })
await box.agent.run({ prompt: "Fix the null-token bug in src/auth.ts and add tests" })
await box.git.createPR({ title: "Fix null token bug", base: "main" })
```

Clone, fix, test, open a pull request, with no agent loop of your own to wire up. You can also pin the output to a schema and get typed data back instead of free text. The built-in agent is a head start, not a requirement: either way you get git, files, logs, and streaming.

It's **agent friendly** in the details too: secrets can be injected into outbound requests without ever entering the box, schedules run a command or a prompt on a cron, and every run records its cost with searchable logs and full history.

On **pricing**, Box is the lowest-cost option in this list for typical agent workloads. It bills active CPU only, at $0.10 per active CPU-hour, and leaves memory free. Agent work spends most of its time waiting on the model, so that idle time isn't charged. If you need a box that stays on all the time, a keep-alive box is a flat $8 a month for 2 vCPU and 4 GB, which is about $0.011 per wall-clock hour.

The **free plan** is ten concurrent boxes and five CPU-hours a month, with no platform fee. Agents use your own model provider key (Anthropic, OpenAI, OpenRouter, ...). A box also auto-pauses when idle and wakes weeks later with its files intact, so a long-lived box per user costs almost nothing between sessions.

Good to know: each box is an isolated container with its own filesystem, process tree, and network stack. Boxes run on AWS `us-east-1` today, with more regions planned, and start from prebuilt runtime images (Node, Python, Go, Ruby, Rust) plus snapshots, with custom Docker images on the way.

**When to use it:** as the default choice for most agent workloads, and the best overall option here on feature set and price: when you want a persistent computer for your agent that takes minutes to set up and plugs into the framework or coding agent you already use, whether you bring your own loop or let Box run the agent for you.

## Daytona: speed and a broad SDK surface

[Daytona](https://www.daytona.io) leads with raw startup speed, advertising sub-90ms cold starts, and pairs it with unlimited session length. The execution surface is its strength: SDKs in five languages (Python, TypeScript, Go, Ruby, Java), a stateful Python interpreter, a VNC desktop, an MCP server, shared volumes, and GPU sandboxes.

```ts
import { Daytona } from "@daytona/sdk"

const daytona = new Daytona()
const sandbox = await daytona.create()
const res = await sandbox.process.codeRun('print("hello from the sandbox")')
console.log(res.result)
```

Billing is plain pay-as-you-go on vCPU and memory by the second, no platform fee, with $200 in starting credits. You bring the agent loop yourself; Daytona gives you a fast, flexible place to run its code.

**When to use it:** when you already have your own agent and want a quick, flexible, multi-language runner, especially if you need very fast starts, a non-TypeScript SDK, or GPUs without a platform fee.

## E2B: the AI-first standard with strong isolation

[E2B](https://e2b.dev) is the one most people picture when they hear "code sandbox for agents," and it helped define the category. Each sandbox runs in a Firecracker microVM with its own kernel, a stronger boundary than plain containers, and it starts fast.

Its real signature is the **Code Interpreter**, a built-in Jupyter server. State survives between calls, so variables and loaded data stick around, and results come back structured, a chart returns as a real image plus its data.

```ts
import { Sandbox } from "@e2b/code-interpreter"

const sbx = await Sandbox.create()
await sbx.runCode("x = 21")              // state persists across calls
const run = await sbx.runCode("print(x * 2)")
console.log(run.logs.stdout)             // ['42']
```

It speaks Python, JS/TS, R, Java, and Bash, offers a desktop-over-VNC variant for computer use, can be self-hosted, and says 94 of the Fortune 100 have signed up. The trade-offs: a monthly platform fee for production limits, a 24-hour session cap, and no GPUs.

**When to use it:** when isolation matters most and you want notebook-style execution with charts and tables out of the box, or a desktop for computer use. The default pick for data-analysis agents and code interpreters at scale.

## Vercel Sandbox: for the frontend and codegen crowd

[Vercel Sandbox](https://vercel.com/docs/sandbox) runs untrusted or generated code in Firecracker microVMs. It's aimed at the v0 and AI-SDK generation of apps: code generation, live previews, and experimentation. Sandboxes are persistent by default, start in milliseconds, and can even run Docker inside them.

```ts
import { Sandbox } from "@vercel/sandbox"

const sandbox = await Sandbox.create()
const result = await sandbox.runCommand({ cmd: "node", args: ["-e", "console.log(2 + 2)"] })
console.log(await result.stdout())
```

Its most notable detail, and the one that fits agents best, is that it bills **active CPU** rather than wall-clock CPU. CPU time spent waiting on the model isn't charged, though provisioned memory still is. It runs on Vercel and reads auth from your project, so it's most natural if you already deploy there.

**When to use it:** when you're already on Vercel and the AI SDK and want a sandbox that drops into that stack for generating, running, and previewing code.

## Modal: the GPU and ML workhorse

[Modal](https://modal.com) came from the serverless-ML world and added sandboxes on top. Its standout is **GPUs**: everything up to H200, B200, and B300, on demand. It's Python-native, scales to zero when idle, and scales out to thousands of containers when busy.

```python
import modal

app = modal.App.lookup("agent-sandbox", create_if_missing=True)
sb = modal.Sandbox.create(app=app, gpu="H100")

p = sb.exec("python", "-c", "import torch; print(torch.cuda.is_available())")
print(p.stdout.read())
sb.terminate()
```

The catch is cost: sandboxes run at a premium over base Modal functions, effective GPU rates sit higher than dedicated GPU providers, and Node.js support is limited.

**When to use it:** when the work is GPU-bound, training, inference, heavy data processing, and you live in Python. If your sandbox needs a GPU right next to the code, Modal is the obvious fit.

## Cloudflare Sandboxes: code execution at the edge

[Cloudflare's Sandbox SDK](https://developers.cloudflare.com/sandbox/) runs isolated containers right next to Workers. Its angle is the **ecosystem and the edge**. If your agent already lives in Workers, Durable Objects, and Workers AI, code execution is one binding away.

```ts
import { DurableObject } from "cloudflare:workers"

export class AgentBox extends DurableObject {
  async run(argv: string[]) {
    const container = this.ctx.container!
    if (!container.running) {
      container.start({
        image: "cloudflare/debian-trixie",
        entrypoint: ["sleep", "infinity"],
        enableInternet: false,
      })
    }
    const proc = await container.exec(argv)
    const out = await proc.output()
    return new TextDecoder().decode(out.stdout)
  }
}

export default {
  async fetch(request, env) {
    const box = env.AGENT_BOX.getByName("agent-box")
    return Response.json({ output: await box.run(["node", "-e", "console.log(2 + 2)"]) })
  },
}
```

Sandbox SDK 1.0 (September 2026) builds on Durable Objects: you get container exec, file helpers, and filesystem snapshots, each instance runs in its own Firecracker microVM, and internet access is off unless you enable it. Preview URLs and the code interpreter from the 0.x SDK are now patterns you write yourself. It also ties into Cloudflare's newer primitives for long-running, durable agents, and backs the managed-agent offering built with Anthropic.

**When to use it:** when you're already building on Cloudflare and want code execution that's a Worker binding away, with global edge placement and durable agents.

## Northflank: the full platform with bring-your-own-cloud

[Northflank](https://northflank.com) is the broadest here: not just sandboxes, but databases, APIs, workers, and CI/CD together, under the same isolation.

Its standout is **deployment flexibility**, microVM isolation (Kata and Cloud Hypervisor) plus gVisor, any container image, unlimited sessions, on-demand GPUs (L4, A100, H100, H200, B200, RTX PRO 6000), and self-serve bring-your-own-cloud across AWS, GCP, Azure, Oracle, and bare metal. Sandbox compute is among the cheapest in this list.

This is the one you reach for when a sandbox alone isn't enough, when the agent needs a database, a queue, and an API next to it under the same security model. It's a platform first: you drive it through its API, CLI, UI, and JavaScript or Python client, and a sandbox is a full service spec, not a one-line call.

**When to use it:** when you need more than a sandbox, persistent agents next to the services they talk to, or strict data-residency rules that mean running everything in your own cloud.

## Freestyle: full Linux VMs for long-running agents

[Freestyle](https://www.freestyle.sh) is the opposite of the quick "run this snippet" sandboxes: it gives your agent a full, hardware-virtualized Linux VM with its own kernel, nested virtualization (Docker, even KVM inside the VM), and full Linux networking with real root access.

It is also built to run for a long time. VMs are persistent, bill only for storage while paused, and resume in under 100ms. Snapshots capture the full machine state, and a running VM can be forked in milliseconds without pausing it, so taking snapshots often is cheap. VMs can go up to 64 GB of RAM on demand.

```ts
import { Freestyle } from "freestyle";

const freestyle = new Freestyle();

const { vm } = await freestyle.vms.create({
  // required: a VM reaches nothing it has not been allowed to
  firewall: { rules: [{ action: "allow", source: {}, destination: { public: true } }] },
});

const result = await vm.exec({ command: "uname -a" });
console.log(result.stdout);

// grow the same VM as the task grows (memory and storage in MiB)
await vm.resize({ cpu: 8, memory: 16 * 1024, storage: 80 * 1024 });
```

**When to use it:** when your agent runs for a long time and needs a real computer, root, its own kernel, Docker, custom networking, rather than a short-lived code runner.

## Fly.io: sandboxing at the infrastructure layer

[Fly.io](https://fly.io/ai) sits one level lower than the rest: it gives you the virtualization, not an agent-shaped wrapper. Its Machines are hardware-isolated Firecracker microVMs that boot any container in under a second. Its persistent variant keeps installed packages and saved files between sessions, so an agent can close today and resume tomorrow.

```bash
# boot a one-off, hardware-isolated microVM from any image
fly machine run ghcr.io/your-org/agent-image --rm
```

You get kernel-level isolation without operating the virtualization stack yourself, in exchange for building more of the agent platform on top. It's the rawest option here, and the most flexible.

**When to use it:** when you want raw, Firecracker-isolated VMs to build your own sandbox or multi-tenant platform on, and you'd rather own the orchestration than adopt someone's opinions.

## Runloop: purpose-built for coding agents (winding down)

[Runloop](https://runloop.ai) was the most coding-agent-focused entry in the first version of this post: devboxes on a custom bare-metal hypervisor, Blueprints for reusable templates, an Agent Gateway that kept real credentials out of the box, and built-in benchmarks and evals.

As of November 2026 its docs say Runloop is winding down, with transition support for existing customers through November 13, 2026 and [migration guides](https://docs.runloop.ai/docs/transitions/overview) to Tensorlake, Modal, and Freestyle. Upstash Box could also be a good fit, since it runs coding agents the same way, with the agent, git, and secrets handling built in. The benchmark product is discontinued.

**When to use it:** don't start a new project on it. If you are already on Runloop, start with its migration guides, and consider Upstash Box as a place to run the same agents.

## How to actually choose

The category looks crowded, but the choice usually comes down to a couple of questions.

**Do you want a built-in agent or just a place to run code?** **Upstash Box** covers both: it's a persistent computer you can drive from your own loop over an SDK, CLI, MCP, or SSH, and it can also run Claude Code, Codex, or OpenCode for you with git and pull requests wired up. If you've already built your own loop, the other providers here fit as well, and the next question narrows them down.

**What's your hardest constraint?** Strong isolation → **E2B** or **Fly.io**. A GPU in the box → **Modal** or **Northflank**. Cold-start speed → **Daytona**. A long-lived VM with root → **Freestyle**. Your existing ecosystem → **Cloudflare** or **Vercel**. Self-hosting → **Northflank**.

**What does the work spend its time doing?** If it mostly *waits* on the model (most agent work does), active-CPU billing saves real money over wall-clock pricing. **Upstash Box** bills active CPU only with memory free, while **Vercel Sandbox** and **Cloudflare** bill active CPU plus memory. If it has to stay on all the time, a Box keep-alive box is a flat $8 a month, below the per-hour rates of the wall-clock providers.

For most teams, **Upstash Box** is the best place to start: it covers the widest range of agent workloads, from a plain shell for your own loop to a built-in coding agent with git, a browser, and schedules, and it is priced low. Add or switch to another provider when you hit a constraint it can't move, such as a GPU or your own cloud.

If Box sounds like the fit, the [quickstart](https://upstash.com/docs/box/overall/quickstart) takes a few minutes. For the same providers (and five more) in tables, with prices and a source for every row, see the [15-provider comparison](/blog/ai-agent-sandbox-providers-compared-2026).

## FAQ

### What is the best sandbox for AI agents in 2026?

For most agent workloads, Upstash Box is the best overall option on feature set and price: it is a persistent computer that is quick to set up, it works with your own agent or a built-in one, and git, a browser, schedules, and secret injection are included. For specific needs, pick a specialist: for a separate kernel per sandbox, E2B, Vercel Sandbox, Freestyle or Fly.io; for GPUs, Modal or Northflank; for your own cloud, Northflank. If you're already on Cloudflare or Vercel, their own sandboxes fit that stack.

### What is an AI agent sandbox?

An isolated environment where an AI agent runs the code it writes, with its own filesystem, shell and network, so a wrong command or a malicious package can't reach your machine, your data or other users.

### Which AI sandbox is cheapest?

For typical agent workloads, Upstash Box. For agents that spend most of their time waiting on the model, it bills active CPU only ($0.10 per active CPU-hour) and leaves memory free, while Vercel Sandbox and Cloudflare bill active CPU plus provisioned memory and the rest bill wall-clock time. For a sandbox that stays on all the time, a keep-alive box is a flat $8 a month for 2 vCPU and 4 GB, about $0.011 per wall-clock hour. The [15-provider comparison](/blog/ai-agent-sandbox-providers-compared-2026) works through the numbers.

### Which sandbox can run Claude Code or Codex inside it?

Upstash Box runs Claude Code, Codex, OpenCode or a custom harness behind `box.agent.run()`. Vercel Sandbox and Fly Sprites ship the CLIs preinstalled, and on most other providers you install the agent yourself and drive it through `exec`.

### What are the best alternatives to E2B?

Daytona for fast starts and more SDK languages, Modal for GPUs, Freestyle for long-running full VMs, Upstash Box for a persistent box with no session cap, a built-in coding agent, and git, browser, and cron tooling, and Vercel Sandbox if you deploy on Vercel.
